# Pandemia

*[Read in English](./README.md)*

Витрина для DayZ-серверов «Pandemia»: список серверов, внутриигровой магазин
предметов с корзиной, профиль игрока (баланс, история покупок, заявки в поддержку) и
блок новостей с последними постами сообщества. Тёмная и светлая тема, переключатель
RU/EN.

Я делаю его как проект для портфолио, чтобы показать, что могу довести реальную
витрину от идеи до задеплоенного сайта: полноценный UX, единый интерфейс,
автоматический деплой и кодовая база, в которую можно добавить бэкенд без
переписывания интерфейса.

Онлайн: <https://runforest1.github.io/pandemia/>

## Зачем я это делаю

Мне нужна была витрина с законченными пользовательскими сценариями — вход, баланс,
корзина, список серверов, поддержка, — а не разовый макет. Дизайн определили два
ограничения:

1. **Всё должно работать на бесплатном статическом хостинге.** GitHub Pages не
   умеет запускать серверный код, поэтому живой сайт не обращается ни к какому
   серверу.
2. **Это не должен быть тупик.** Интерфейс отделён от источника данных, поэтому
   подключение реального бэкенда позже — это замена слоя данных, а не переписывание
   интерфейса.

## Как устроен проект: фронтенд и бэкенд

В репозитории две независимые части:

```
src/       — фронтенд. Единственная часть, которая реально деплоится на GitHub Pages.
server/    — бэкенд (Express). Полностью рабочий, но не задеплоен и не используется
             живым сайтом — задел на будущее.
```

### Фронтенд (`src/`) — то, что в продакшене

Сайт **полностью статический**. Всё, что обычно требует бэкенда, эмулируется на
клиенте через `localStorage`:

- **Вход через Steam** — вместо настоящего похода на steamcommunity.com сразу
  логинит демо-пользователя и открывает профиль (`src/auth/AuthProvider.tsx`,
  `src/api/localAccount.ts`).
- **Баланс и пополнение** — в интерфейсе честно помечены как тестовый режим; сумма
  зачисляется сразу и хранится локально в браузере.
- **Корзина, история покупок, заявки в поддержку, настройки профиля** — тоже
  локально (`src/cart/`, `src/api/localOrders.ts`, `src/api/localTickets.ts`).
- **Новости** — последние посты сообщества проекта во ВКонтакте, вручную скопированные
  в `src/data/news.ts` (живой ленты нет).
- **Список серверов** — статус и онлайн пока задаются вручную, а не читаются с
  серверов.

На GitHub Pages нет сервера, который что-то считал бы и хранил в базе, поэтому вся
«бизнес-логика» — честная клиентская симуляция, и везде, где это важно, интерфейс
прямо говорит о тестовом режиме.

### Бэкенд (`server/`) — задел на будущее

Отдельный рабочий Express-сервер, который не участвует в деплое на GitHub Pages. Я
оставляю его в репозитории на случай переезда на хостинг с поддержкой Node.js:

- **Steam OpenID 2.0** (`server/src/auth/steam.ts`) — настоящий вход через Steam:
  редирект на `steamcommunity.com`, проверка подписи ответа, SteamID64, сессия в
  httpOnly JWT-куке. Никнейм и аватар берутся из Steam Web API (бесплатный ключ на
  <https://steamcommunity.com/dev/apikey>, переменная `STEAM_API_KEY`) или, без
  ключа, из публичного XML-профиля как запасной путь.
- **Баланс** (`server/src/routes/balance.ts`) — пока тоже заглушка без платёжного
  провайдера (сумма помечается оплаченной сразу), но уже с настоящим сервером, базой
  и API. Чтобы подключить провайдера (YooKassa/CloudPayments/Robokassa),
  `POST /api/balance/topup` должен создавать платёж в статусе `pending` и
  подтверждать его по вебхуку провайдера, а не помечать `paid` сразу.

Чтобы фронтенд снова работал с этим бэкендом вместо `localStorage`, нужно
переключить `AuthProvider` (`src/auth/AuthProvider.tsx`) обратно на
`fetchCurrentUser`/`devLogin`/`STEAM_LOGIN_URL` из `src/api/auth.ts` и
`topUpBalance`/`fetchBalanceHistory` из `src/api/balance.ts` — эти файлы на месте и
по-прежнему работают с `server/`.

## Запуск локально

```bash
npm install
npm run dev
```

Открыть <http://localhost:5173> — сайт полностью работоспособен, бэкенд не нужен.

Чтобы запустить ещё и бэкенд (для разработки или проверки серверной части):

```bash
npm run server:install
cp server/.env.example server/.env
# сгенерировать секрет сессии:
openssl rand -hex 32
# и вписать его в server/.env как SESSION_SECRET

npm run dev:full   # фронтенд (5173) + бэкенд (4000), с прокси для /api и /auth
```

Для бэкенда нужен Node.js ≥ 22.5 (используется встроенный `node:sqlite`).

Остальные скрипты:

```bash
npm run build          # прод-сборка, base "/"
npm run build:pages    # прод-сборка, base "/pandemia/" — для GitHub Pages
npm run preview        # просмотр сборки с base "/"
npm run preview:pages  # просмотр сборки для Pages на http://localhost:4173/pandemia/
npm run lint           # eslint
```

## Структура проекта

```
src/
  components/             # atomic design: atoms / molecules / organisms / templates
  auth/                   # AuthProvider, RequireAuth, useAuth
  cart/                   # CartProvider, useCart
  api/                    # эмуляция на localStorage + клиент для настоящего бэкенда

server/                   # Express-бэкенд (не задеплоен)
public/                   # 404.html для SPA-фолбэка на GitHub Pages
```

## Дизайн

- **Тема:** тёмная/светлая, переключается кнопкой в шапке, сохраняется в
  `localStorage`, при первом визите учитывает `prefers-color-scheme`.
- **Язык:** RU/EN, переключается кнопкой в шапке (`src/i18n`).
- **Палитра и типографика:** токены в `src/App.css`, для компонентов MUI
  продублированы в `src/theme/palette.ts`.

## Деплой на GitHub Pages

Автодеплой настроен в `.github/workflows/deploy-pages.yml`: каждый push в `main`
собирает `src/` и публикует результат. Единственный ручной шаг — один раз
переключить источник Pages: **Settings → Pages → Build and deployment → Source →
GitHub Actions**. В режиме по умолчанию «Deploy from a branch» GitHub отдаёт файлы
репозитория как есть, без сборки, и браузер пытается загрузить несобранный
`src/main.tsx` — отсюда ошибка MIME-типа `text/html`.

Убедиться, что деплой прошёл, можно во вкладке **Actions**: зелёный запуск
`Deploy static site to GitHub Pages` — сайт живой. Если после переключения источника
запусков ещё нет — запушьте коммит или запустите воркфлоу вручную через
**Run workflow**.

Как это работает:

- `vite.config.ts` собирает сайт с `base: '/pandemia/'` (имя репозитория) только
  когда воркфлоу выставляет `GITHUB_PAGES=true`; локальная разработка работает от
  корня.
- GitHub Pages не умеет отдавать `index.html` для произвольных маршрутов SPA
  (`/pandemia/profile` получил бы настоящий 404). `public/404.html` перехватывает
  такой запрос и редиректит на `index.html`, закодировав исходный путь в query;
  скрипт в `index.html` раскодирует его обратно до того, как React Router прочитает
  `location`
  ([rafgraph/spa-github-pages](https://github.com/rafgraph/spa-github-pages)).

## Что дальше
